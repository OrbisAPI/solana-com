# Solana'da Gizli Transfer Token'ları İhraç Etme

Bu kılavuz **ihraçcılar** içindir: Gizli Transfer uzantısını kullanan bir
Token-2022 mint'i oluşturan ve yöneten ekipler. Mint oluşturma sırasında
alacağınız kararları ve mint'in ömrü boyunca gerçekleştireceğiniz işlemleri
kapsar. Tutucu tarafı akışı (yatırma, uygulama, transfer, çekme) için adım adım
sayfalara, bu token'ları bir üründe desteklemek içinse
[Entegrasyon Kılavuzu](/docs/tokens/extensions/confidential-transfer/integration-guide)'na
bakın.

Gizli transferler, hesap adresleri, mint ve sahipleri herkese açık bırakırken
transfer tutarlarını ve hesap bakiyelerini şifreli tutar. Zincir üstü kanıt
doğrulaması için ZK ElGamal Proof Program'a dayanırlar; bu nedenle mint,
yalnızca söz konusu programın etkin olduğu kümelerde kullanılabilir.

## Oluşturma sırasında aldığınız kararlar

Gizli Transfer uzantısı, mint başlatılmadan önce başlatılmalıdır ve sonradan
eklenemez. Oluşturma sırasında şunlara karar verirsiniz:

- **Onay politikası**: hesapların izin gerektirmeksizin gizli transferlere
  katılıp katılamayacağı (`auto`) ya da mint'in gizli transfer yetkisi
  (`manual`) tarafından onaylanması gerekip gerekmediği.
- **Denetçi**: belirli bir tarafın mint için tüm transfer tutarlarını şifresini
  çözebilmesi amacıyla global bir denetçi ElGamal pubkey ayarlanıp
  ayarlanmayacağı. İsteğe bağlıdır ve sonradan değiştirilebilir.
- **İsteğe bağlı eşlik eden uzantılar**: gizli transfer ücretleri (transfer
  ücreti uzantısıyla eşleştirilmiş) ve gizli mint/burn; her ikisi de aşağıda ele
  alınmaktadır. Bunların da oluşturma sırasında başlatılması gerekir.

## Gizli bir mint oluşturma

CLI, onay politikasını `--enable-confidential-transfers auto` veya `manual` ile
belirler; `auto` herhangi bir sahipten kendi hesabını yapılandırmasına izin
verirken, `manual` bunu gizli transfer yetkisinin (varsayılan olarak mint
yetkisine düşer) onayı arkasına kilitler. İstemci yolları, aynı ayarları
`ConfidentialTransferMint` parametreleri aracılığıyla alır: bir yetki, otomatik
onay bayrağı ve isteğe bağlı bir denetçi anahtarı. Hem onay politikası hem de
denetçi sonradan değiştirilebilir (bkz.
[Denetçi yapılandırma](#configure-an-auditor)); yalnızca uzantının varlığı
oluşturma sırasında sabitlenir.

<CodeTabs>

```terminal !! title="create-confidential-mint.sh"
$ spl-token --program-id TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb create-token --enable-confidential-transfers auto
```

```rust !! title="create-confidential-mint.rs"
use spl_token_client::token::ExtensionInitializationParams;

let extensions = vec![ExtensionInitializationParams::ConfidentialTransferMint {
    authority: Some(authority.pubkey().into()),
    auto_approve_new_accounts: true, // false for a manual approve policy
    auditor_elgamal_pubkey: None,    // Some(pubkey) to set a global auditor
}];

token
    .create_mint(&mint_authority, freeze_authority.as_ref(), extensions, &[&mint_keypair])
    .await?;
```

```ts !! title="create-confidential-mint.ts"
import { getCreateAccountInstruction } from "@solana-program/system";
import {
  extension,
  getMintSize,
  getInitializeConfidentialTransferMintInstruction,
  getInitializeMintInstruction,
  TOKEN_2022_PROGRAM_ADDRESS
} from "@solana-program/token-2022";

// Size the mint account to include the confidential transfer extension.
const space = BigInt(
  getMintSize([
    extension("ConfidentialTransferMint", {
      authority: authority.address,
      autoApproveNewAccounts: true, // false for a manual approve policy
      auditorElgamalPubkey: null // an ElGamal pubkey Address to set an auditor
    })
  ])
);
const rent = await rpc.getMinimumBalanceForRentExemption(space).send();

// Create the account, initialize the extension, then initialize the mint, in one
// transaction. The extension instruction must come before InitializeMint.
const instructions = [
  getCreateAccountInstruction({
    payer,
    newAccount: mint, // mint keypair signer
    lamports: rent,
    space,
    programAddress: TOKEN_2022_PROGRAM_ADDRESS
  }),
  getInitializeConfidentialTransferMintInstruction({
    mint: mint.address,
    authority: authority.address,
    autoApproveNewAccounts: true,
    auditorElgamalPubkey: null
  }),
  getInitializeMintInstruction({
    mint: mint.address,
    decimals,
    mintAuthority: mintAuthority.address,
    freezeAuthority: null
  })
];
// Sign with the payer and mint keypair, then send.
```

</CodeTabs>

## Denetçi yapılandırma

Global bir denetçi, mint üzerinde saklanan bir ElGamal pubkey'dir.
Ayarlandığında, her gizli transfer tutarını bu anahtar altında ek olarak
şifreler; böylece ilgili gizli anahtarı elinde bulunduran kişi, mint için tüm
transfer tutarlarının şifresini çözebilir. Gizli transferlerin denetim ve
uyumluluk gereksinimleriyle uyumlu kalmasının yolu budur: kamuoyu hiçbir şey
görmez, denetçi her şeyi görür.

Gizli transfer yetkilisi, denetçiyi istediği zaman ayarlayabilir, değiştirebilir
veya kaldırabilir. Aynı işlem onay politikasını da günceller. CLI'da denetçi
anahtarı, bir ElGamal pubkey'inin base64 kodlamasıdır; kaldırmak için
`--auditor-pubkey none`, politikayı değiştirmek için
`--approve-policy auto|manual` kullanın.

Rotasyon yalnızca gelecekteki transferleri etkiler. Zincirde halihazırda bulunan
işlemlerdeki tutarlar, yürütüldükleri sırada aktif olan denetçi anahtarıyla
şifreli kalmaya devam eder; bu nedenle geçmiş aktiviteyi çözmeniz gerekiyorsa
eski denetçi anahtarlarını saklayın.

<CodeTabs>

```terminal !! title="update-confidential-settings.sh"
$ spl-token update-confidential-transfer-settings <MINT_PUBKEY> --auditor-pubkey <AUDITOR_ELGAMAL_PUBKEY>
```

```rust !! title="update-confidential-settings.rs"
token
    .confidential_transfer_update_mint(
        &authority,
        true,                         // auto_approve_new_account
        Some(auditor_elgamal_pubkey), // None to clear the auditor
        &[&authority_keypair],
    )
    .await?;
```

```ts !! title="update-confidential-settings.ts"
import { getUpdateConfidentialTransferMintInstruction } from "@solana-program/token-2022";

const ix = getUpdateConfidentialTransferMintInstruction({
  mint,
  authority, // confidential transfer authority (signer)
  autoApproveNewAccounts: true,
  auditorElgamalPubkey // an ElGamal pubkey Address, or null to clear
});
```

</CodeTabs>

<Callout type="warn">
  Denetçi gizli anahtarı, mint için her transfer tutarını çözebilir. Bunu bir
  imzalama anahtarıyla aynı titizlikte saklayın ve rotasyon planı yapın.
  Denetçinin `None` olarak ayarlanması, hesap sahiplerinin kendileri dışında
  herkes için tutar görünürlüğünü devre dışı bırakır.
</Callout>

## Hesap onayı (manuel politika)

Manuel onay politikasıyla, gizli transferler için yapılandırılmış bir hesap,
gizli transfer yetkilisi tarafından onaylanana kadar gizli işlem yapamaz. Bu,
ihraçcılara izin verilenler listesindeki veya KYC'den geçmiş katılımcılar için
bir kontrol noktası sağlar. CLI bir onay komutu sunmadığından, onay işlemi bir
istemci aracılığıyla gerçekleştirilir.

<CodeTabs>

```rust !! title="approve-account.rs"
token
    .confidential_transfer_approve_account(
        &token_account,
        &authority,
        &[&authority_keypair],
    )
    .await?;
```

```ts !! title="approve-account.ts"
import { getApproveConfidentialTransferAccountInstruction } from "@solana-program/token-2022";

const ix = getApproveConfidentialTransferAccountInstruction({
  token, // the token account to approve
  mint,
  authority // confidential transfer authority (signer)
});
```

</CodeTabs>

## Gizli transfer ücretleri

Mint'iniz bir [transfer ücreti](/docs/tokens/extensions/transfer-fees) alıyorsa
ve transferler gizliyse, ücretin de gizli olarak tutulması gerekir.
`ConfidentialTransferFeeConfig` uzantısı bunu yönetir ve mint oluşturulurken hem
transfer ücreti hem de gizli transfer uzantılarıyla birlikte başlatılır.

Tutulan ücretler, alıcı hesaplarda şifreli olarak birikir, mint'e aktarılır ve
ardından tutulan miktarı çekme yetkisi tarafından çekilir. Her ücret tutarı
boyunca şifreli kalır. Bunların hiçbiri CLI üzerinden erişilebilir değildir.
Tutulan miktarı çekme yetkisinin ElGamal gizli anahtarı, tutulan ücret
tutarlarını çözebilir; bu durum, genel ücret parametreleriyle birleştiğinde
transfer tutarları hakkında bilgi açığa çıkarabilir; dolayısıyla bu anahtara
hassas bir veri olarak muamele edin.

### Ücret yapılandırmasını başlat

Bunu `ConfidentialTransferMint` ve transfer ücreti yapılandırmasıyla birlikte
aynı mint oluşturma işlemine dahil edin.

<CodeTabs>

```rust !! title="init-confidential-fee.rs"
use spl_token_client::token::ExtensionInitializationParams;

ExtensionInitializationParams::ConfidentialTransferFeeConfig {
    authority: Some(authority.pubkey().into()),
    withdraw_withheld_authority_elgamal_pubkey: withdraw_withheld_elgamal_pubkey,
};
```

```ts !! title="init-confidential-fee.ts"
import { getInitializeConfidentialTransferFeeInstruction } from "@solana-program/token-2022";

const ix = getInitializeConfidentialTransferFeeInstruction({
  mint,
  authority, // authority allowed to change the withdraw withheld ElGamal key
  withdrawWithheldAuthorityElGamalPubkey // ElGamal pubkey Address
});
```

</CodeTabs>

### Tutulan ücretleri topla ve çek

Toplama işlemi, şifrelenmiş tutulan ücretleri hesaplardan mint'e taşır; çekme
işlemi ise bunları mint'ten seçilen bir hesaba aktarır. İki yetki dahildir ve
her ikisi de mint yetkisinden farklı olabilir:

- **Gizli transfer ücreti yetkisi** (`ConfidentialTransferFeeConfig` üzerinde
  ayarlanan `authority`) toplamayı etkinleştirir veya devre dışı bırakır.
- **Tutulanları çekme yetkisi** (transfer ücreti uzantısının
  `TransferFeeConfig`'inden) toplanan ücretleri mint'ten çeker.

Çekme işlemleri, satır içi sağlanan veya bağlam durum hesaplarında doğrulanan
bir eşitlik ve bir aralık kanıtı gerektirir.

<CodeTabs>

```rust !! title="harvest-withdraw-fees.rs"
// Permissionless: move withheld fees from accounts into the mint.
token
    .confidential_transfer_harvest_withheld_tokens_to_mint(&[&source_account])
    .await?;

// Withdraw withheld fees from the mint (requires the withdraw withheld authority).
token
    .confidential_transfer_withdraw_withheld_tokens_from_mint(
        &destination_account,
        &withdraw_withheld_authority,
        None, // proof context state account, supplied inline if None
        None, // withheld tokens info, fetched if None
        &withdraw_withheld_elgamal_keypair,
        &destination_elgamal_pubkey,
        &new_decryptable_available_balance,
        &[&withdraw_withheld_authority_keypair],
    )
    .await?;
```

```ts !! title="harvest-withdraw-fees.ts"
import {
  getEnableHarvestToMintInstruction,
  getHarvestWithheldTokensToMintForConfidentialTransferFeeInstruction
} from "@solana-program/token-2022";

// Allow accounts to harvest their withheld fees to the mint, signed by the
// confidential transfer fee authority.
const enableIx = getEnableHarvestToMintInstruction({ mint, authority });

// Permissionless: move withheld fees from accounts into the mint.
const harvestIx =
  getHarvestWithheldTokensToMintForConfidentialTransferFeeInstruction({
    mint,
    sources: [sourceAccount]
  });
```

</CodeTabs>

JS istemcisinde, toplanan ücretleri mint'ten çekmek
(`getWithdrawWithheldTokensFromMintForConfidentialTransferFeeInstruction`)
ayrıca bağlam durum hesaplarında doğrulanan bir eşitlik ve bir aralık kanıtı
gerektirir; bu nedenle gizli bir transferle aynı kanıt hesabı modelini izler.

## Gizli mint ve yakma

`ConfidentialMintBurn` uzantısı, mint yetkisinin toplam arzı şifreli tutarak
doğrudan gizli bakiyelere karşı arz yayınlamasına ve yakmasına olanak tanır. Bu
uzantıya sahip bir mint, ortak mevduat ve çekme yolunu devre dışı bırakır; zira
tokenlar yalnızca gizli olarak var olur. Tam model için
[protokol belgelerine](https://www.solana-program.com/docs/confidential-balances)
bakın.

<Callout type="info">
  Gizli mint/yakma işlemi en kolay şekilde Rust `spl-token-client` aracılığıyla
  gerçekleştirilir; bu araç gerekli kanıtları oluşturur ve işlemleri sizin için
  sıralar. `@solana-program/token-2022` JS istemcisi düşük seviyeli talimat
  oluşturucularıyla (`getConfidentialMintInstruction`,
  `getConfidentialBurnInstruction` ve benzerleri) birlikte gelir; ancak
  kanıtları oluşturan üst düzey bir yardımcı içermez ve CLI komutları da
  bulunmaz, bu nedenle aşağıdaki örnekler yalnızca Rust içindir.
</Callout>

Uzantıyı mint oluşturma sırasında başlatın, ardından zaman içinde arzı mint
edin, burn edin ve mutabık kılın. Mint işlemi, alıcının gizli bakiyesine
şifrelenmiş bir miktar ekler; burn işlemi ise şifrelenmiş bir miktarı daha sonra
arza dahil edilecek bekleyen bir burn'e aktarır. Her ikisi de gizli bir transfer
gibi kanıtlar oluşturur.

<CodeTabs>

```rust !! title="confidential-mint-burn.rs"
use spl_token_client::token::ExtensionInitializationParams;

// 1. Initialize at creation (alongside ConfidentialTransferMint).
ExtensionInitializationParams::ConfidentialMintBurn {
    supply_elgamal_pubkey, // encrypts the confidential supply
    decryptable_supply,    // AES ciphertext of the initial supply (zero)
};

// 2. Mint an encrypted amount into a recipient's confidential balance.
token
    .confidential_transfer_mint(
        &mint_authority,
        &destination_account,
        None, // equality proof account
        None, // ciphertext validity proof account
        None, // range proof account
        mint_amount,
        &supply_elgamal_keypair,
        &destination_elgamal_pubkey,
        auditor_elgamal_pubkey, // Option
        &supply_aes_key,
        None, // supply account info, fetched if None
        &[&mint_authority_keypair],
    )
    .await?;

// 3. Burn an encrypted amount from a holder's confidential balance into the
//    mint's pending burn. Generates proofs like a confidential transfer.
token
    .confidential_transfer_burn(
        &owner,
        &source_account,
        None, // equality proof account
        None, // ciphertext validity proof account
        None, // range proof account
        burn_amount,
        &source_elgamal_keypair,
        &supply_elgamal_pubkey,
        auditor_elgamal_pubkey, // Option
        &source_aes_key,
        None, // burn account info, fetched if None
        &[&owner_keypair],
    )
    .await?;

// 4. Fold the accumulated pending burn into the confidential supply.
token
    .confidential_transfer_apply_pending_burn(&mint_authority, &[&mint_authority_keypair])
    .await?;
```

</CodeTabs>

Arz şifreleme anahtarını `confidential_transfer_rotate_supply_elgamal_pubkey`
ile döndürün (önce bekleyen burn'ün sıfır olması gerekir) ve okunabilir arz
şifreli metnini `confidential_transfer_update_decrypt_supply` ile yenileyin.

## Operasyonel ve uyumluluk değerlendirmeleri

- **Denetçi anahtarı saklanması.** Bir denetçi belirlediyseniz, denetçi gizli
  anahtarı yüksek değerli bir şifre çözme anahtarıdır. Dikkatli bir şekilde
  saklayın ve döndürün; kuruluşunuzda (veya hangi düzenleyicide) bulunacağına
  karar verin.
- **Uyumluluk tutumu.** Adresler herkese açık kalmaya devam ettiğinden adres
  tarama ve karşı taraf grafik analizi çalışmaya devam eder. Miktara dayalı
  izleme, denetçi anahtarına veya hesap sahiplerinin seçici açıklamasına
  bağlıdır. Başlatmadan önce yaklaşımınıza karar verin.
- **Hesap sahiplerini dahil etme.** Gizli bir hesabın yapılandırılması,
  sahibinin imzasını gerektirir. Kullanıcılar için hesapları sorunsuz biçimde
  sağlamak amacıyla, onların bir kez ElGamal anahtarı kaydetmelerini ve
  [Entegrasyon Kılavuzu](/docs/tokens/extensions/confidential-transfer/integration-guide#creating-and-configuring-accounts)'nda
  açıklanan kayıt defteri yolunu kullanmalarını sağlayın.
- **İşlem sayısı.** Kanıtlar günümüzdeki işlem boyutu sınırını aştığından, gizli
  bir transfer şu anda birkaç bağımlı işlemi kapsamaktadır. İşlem formatı v1
  (Agave v4.2 ile kullanıma sunulmaktadır) bu sınırı yükseltmekte ve tek bir
  zincir üstü işleme olanak tanıması beklenmektedir.
