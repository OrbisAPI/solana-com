# Ausgabe von Confidential Transfer Tokens auf Solana

Dieser Leitfaden richtet sich an **Aussteller**: Teams, die einen
Token-2022-Mint erstellen und betreiben, der die Confidential
Transfer-Erweiterung verwendet. Er behandelt die Entscheidungen, die Sie bei der
Mint-Erstellung treffen, sowie die Vorgänge, die Sie während der Lebensdauer des
Mints durchführen. Informationen zum Ablauf auf Halterseite (Einzahlung,
Anwenden, Übertragung, Auszahlung) finden Sie in den Schritt-für-Schritt-Seiten,
und zur Unterstützung dieser Tokens in einem Produkt lesen Sie den
[Integration Guide](/docs/tokens/extensions/confidential-transfer/integration-guide).

Vertrauliche Übertragungen halten Übertragungs­beträge und Konten­salden
verschlüsselt, während Kontenadressen, der Mint und die Eigentümer öffentlich
bleiben. Sie basieren auf dem ZK ElGamal Proof Program zur
Onchain-Proof-Verifizierung, sodass der Mint auf Clustern verwendet werden kann,
auf denen dieses Programm aktiviert ist.

## Entscheidungen bei der Erstellung

Die Confidential Transfer-Erweiterung muss vor der Mint initialisiert werden und
kann später nicht mehr hinzugefügt werden. Bei der Erstellung entscheiden Sie:

- **Genehmigungsrichtlinie**: Ob Konten sich ohne Genehmigung in vertrauliche
  Transfers einschreiben dürfen (`auto`) oder von der Confidential
  Transfer-Autorität der Mint genehmigt werden müssen (`manual`).
- **Prüfer**: Ob ein globaler ElGamal-pubkey für einen Prüfer festgelegt werden
  soll, damit eine bestimmte Partei jeden Transferbetrag für die Mint
  entschlüsseln kann. Optional und kann später geändert werden.
- **Optionale Begleiterweiterungen**: Vertrauliche Transfer-Fee (in Kombination
  mit der Transfer-Fee-Erweiterung) und vertrauliches Mint/Burn, beide unten
  beschrieben. Diese müssen ebenfalls bei der Erstellung initialisiert werden.

## Eine vertrauliche Mint erstellen

Die CLI legt die Genehmigungsrichtlinie mit
`--enable-confidential-transfers auto` oder `manual` fest; `auto` erlaubt es
jedem Inhaber, sein eigenes Konto zu konfigurieren, während `manual` dies an die
Genehmigung durch die Confidential Transfer-Autorität (die standardmäßig der
Mint-Autorität entspricht) knüpft. Die Client-Pfade verwenden dieselben
Einstellungen über die `ConfidentialTransferMint`-Parameter: eine Autorität, das
Auto-Approve-Flag und einen optionalen Prüferschlüssel. Sowohl die
Genehmigungsrichtlinie als auch der Prüfer können später geändert werden (siehe
[Prüfer konfigurieren](#configure-an-auditor)); nur das Vorhandensein der
Erweiterung selbst ist bei der Erstellung festgelegt.

<CodeTabs>

```terminal !! title="create-confidential-mint.sh"
$ spl-token --program-id TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb create-token --enable-confidential-transfers auto
```

```rust !! title="create-confidential-mint.rs"
use spl_token_client::token::ExtensionInitializationParams;

let extensions = vec![ExtensionInitializationParams::ConfidentialTransferMint {
    authority: Some(authority.pubkey().into()),
    auto_approve_new_accounts: true, // false for a manual approve policy
    auditor_elgamal_pubkey: None,    // Some(pubkey) to set a global auditor
}];

token
    .create_mint(&mint_authority, freeze_authority.as_ref(), extensions, &[&mint_keypair])
    .await?;
```

```ts !! title="create-confidential-mint.ts"
import { getCreateAccountInstruction } from "@solana-program/system";
import {
  extension,
  getMintSize,
  getInitializeConfidentialTransferMintInstruction,
  getInitializeMintInstruction,
  TOKEN_2022_PROGRAM_ADDRESS
} from "@solana-program/token-2022";

// Size the mint account to include the confidential transfer extension.
const space = BigInt(
  getMintSize([
    extension("ConfidentialTransferMint", {
      authority: authority.address,
      autoApproveNewAccounts: true, // false for a manual approve policy
      auditorElgamalPubkey: null // an ElGamal pubkey Address to set an auditor
    })
  ])
);
const rent = await rpc.getMinimumBalanceForRentExemption(space).send();

// Create the account, initialize the extension, then initialize the mint, in one
// transaction. The extension instruction must come before InitializeMint.
const instructions = [
  getCreateAccountInstruction({
    payer,
    newAccount: mint, // mint keypair signer
    lamports: rent,
    space,
    programAddress: TOKEN_2022_PROGRAM_ADDRESS
  }),
  getInitializeConfidentialTransferMintInstruction({
    mint: mint.address,
    authority: authority.address,
    autoApproveNewAccounts: true,
    auditorElgamalPubkey: null
  }),
  getInitializeMintInstruction({
    mint: mint.address,
    decimals,
    mintAuthority: mintAuthority.address,
    freezeAuthority: null
  })
];
// Sign with the payer and mint keypair, then send.
```

</CodeTabs>

## Einen Prüfer konfigurieren

Ein globaler Prüfer ist ein ElGamal-pubkey, der auf der Mint gespeichert ist.
Wenn dieser festgelegt ist, verschlüsselt jeder vertrauliche Transfer seinen
Betrag zusätzlich unter diesem Schlüssel, sodass derjenige, der den
entsprechenden geheimen Schlüssel besitzt, alle Transferbeträge für die Mint
entschlüsseln kann. So bleiben vertrauliche Transfers mit Prüf- und
Compliance-Anforderungen kompatibel: Die Öffentlichkeit sieht nichts, der Prüfer
sieht alles.

Die Autorität für vertrauliche Übertragungen kann den Auditor jederzeit
festlegen, rotieren oder entfernen. Dieselbe Operation aktualisiert auch die
Genehmigungsrichtlinie. In der CLI ist der Auditor-Schlüssel eine
Base64-Kodierung eines ElGamal-öffentlichen Schlüssels; übergeben Sie
`--auditor-pubkey none`, um ihn zu entfernen, und
`--approve-policy auto|manual`, um die Richtlinie zu ändern.

Die Rotation betrifft nur zukünftige Übertragungen. Beträge in bereits on-chain
befindlichen Transaktionen bleiben mit dem Auditor-Schlüssel verschlüsselt, der
zum Zeitpunkt ihrer Ausführung aktiv war. Bewahren Sie daher alte
Auditor-Schlüssel auf, wenn Sie historische Aktivitäten entschlüsseln müssen.

<CodeTabs>

```terminal !! title="update-confidential-settings.sh"
$ spl-token update-confidential-transfer-settings <MINT_PUBKEY> --auditor-pubkey <AUDITOR_ELGAMAL_PUBKEY>
```

```rust !! title="update-confidential-settings.rs"
token
    .confidential_transfer_update_mint(
        &authority,
        true,                         // auto_approve_new_account
        Some(auditor_elgamal_pubkey), // None to clear the auditor
        &[&authority_keypair],
    )
    .await?;
```

```ts !! title="update-confidential-settings.ts"
import { getUpdateConfidentialTransferMintInstruction } from "@solana-program/token-2022";

const ix = getUpdateConfidentialTransferMintInstruction({
  mint,
  authority, // confidential transfer authority (signer)
  autoApproveNewAccounts: true,
  auditorElgamalPubkey // an ElGamal pubkey Address, or null to clear
});
```

</CodeTabs>

<Callout type="warn">
  Der geheime Auditor-Schlüssel kann jeden Überweisungsbetrag für den Mint
  entschlüsseln. Verwahren Sie ihn mit derselben Sorgfalt wie einen
  Signing-Schlüssel, und planen Sie eine Rotation ein. Wenn der Auditor auf
  `None` gesetzt wird, wird die Betragsanzeige für alle deaktiviert, außer für
  die Konten-Inhaber selbst.
</Callout>

## Konten genehmigen (manuelle Richtlinie)

Mit einer manuellen Genehmigungsrichtlinie kann ein für vertrauliche
Übertragungen konfiguriertes Konto keine vertraulichen Transaktionen
durchführen, bis die Autorität für vertrauliche Übertragungen es genehmigt. Dies
gibt Ausstellern eine Kontrollfunktion für Allowlist- oder KYC-geprüfte
Teilnehmer. Die CLI bietet keinen Genehmigungsbefehl, daher erfolgt die
Genehmigung über einen Client.

<CodeTabs>

```rust !! title="approve-account.rs"
token
    .confidential_transfer_approve_account(
        &token_account,
        &authority,
        &[&authority_keypair],
    )
    .await?;
```

```ts !! title="approve-account.ts"
import { getApproveConfidentialTransferAccountInstruction } from "@solana-program/token-2022";

const ix = getApproveConfidentialTransferAccountInstruction({
  token, // the token account to approve
  mint,
  authority // confidential transfer authority (signer)
});
```

</CodeTabs>

## Vertrauliche Überweisungsgebühren

Wenn Ihr Mint eine [Überweisungsgebühr](/docs/tokens/extensions/transfer-fees)
erhebt und Übertragungen vertraulich sind, muss die Fee ebenfalls vertraulich
einbehalten werden. Die `ConfidentialTransferFeeConfig`-Erweiterung übernimmt
dies und wird bei der Mint-Erstellung zusammen mit der Überweisungsgebühr und
den Erweiterungen für vertrauliche Übertragungen initialisiert.

Einbehaltene Gebühren werden verschlüsselt auf den Empfänger-Konten angesammelt,
zum Mint übertragen und anschließend von der Autorität zum Abheben einbehaltener
Beträge abgehoben. Jeder Gebührenbetrag bleibt dabei durchgehend verschlüsselt.
Dies ist über die CLI nicht zugänglich. Der geheime ElGamal-Schlüssel der
Abhebe-Autorität kann einbehaltene Gebührenbeträge entschlüsseln, was in
Kombination mit den öffentlichen Gebührenparametern Rückschlüsse auf
Überweisungsbeträge ermöglichen kann – behandeln Sie diesen Schlüssel daher als
sensibel.

### Fee-Konfiguration initialisieren

Fügen Sie dies zusammen mit `ConfidentialTransferMint` und der
Transfer-Fee-Konfiguration bei der Erstellung desselben Mint ein.

<CodeTabs>

```rust !! title="init-confidential-fee.rs"
use spl_token_client::token::ExtensionInitializationParams;

ExtensionInitializationParams::ConfidentialTransferFeeConfig {
    authority: Some(authority.pubkey().into()),
    withdraw_withheld_authority_elgamal_pubkey: withdraw_withheld_elgamal_pubkey,
};
```

```ts !! title="init-confidential-fee.ts"
import { getInitializeConfidentialTransferFeeInstruction } from "@solana-program/token-2022";

const ix = getInitializeConfidentialTransferFeeInstruction({
  mint,
  authority, // authority allowed to change the withdraw withheld ElGamal key
  withdrawWithheldAuthorityElGamalPubkey // ElGamal pubkey Address
});
```

</CodeTabs>

### Einbehaltene Fee einsammeln und abheben

Beim Einsammeln werden die verschlüsselten einbehaltenen Fee von den Konten in
den Mint verschoben; beim Abheben werden sie aus dem Mint auf ein gewähltes
Konto übertragen. Dabei sind zwei Autoritäten beteiligt, die sich beide von der
Mint-Autorität unterscheiden können:

- Die **Confidential-Transfer-Fee-Autorität** (die `authority`, die auf
  `ConfidentialTransferFeeConfig` gesetzt ist) aktiviert oder deaktiviert das
  Einsammeln.
- Die **Withdraw-Withheld-Autorität** (aus dem `TransferFeeConfig` der
  Transfer-Fee-Erweiterung) hebt die eingesammelten Fee aus dem Mint ab.

Abhebungen erfordern einen Gleichheits- und einen Bereichsnachweis, der inline
bereitgestellt oder in Kontextzustands-Konten verifiziert wird.

<CodeTabs>

```rust !! title="harvest-withdraw-fees.rs"
// Permissionless: move withheld fees from accounts into the mint.
token
    .confidential_transfer_harvest_withheld_tokens_to_mint(&[&source_account])
    .await?;

// Withdraw withheld fees from the mint (requires the withdraw withheld authority).
token
    .confidential_transfer_withdraw_withheld_tokens_from_mint(
        &destination_account,
        &withdraw_withheld_authority,
        None, // proof context state account, supplied inline if None
        None, // withheld tokens info, fetched if None
        &withdraw_withheld_elgamal_keypair,
        &destination_elgamal_pubkey,
        &new_decryptable_available_balance,
        &[&withdraw_withheld_authority_keypair],
    )
    .await?;
```

```ts !! title="harvest-withdraw-fees.ts"
import {
  getEnableHarvestToMintInstruction,
  getHarvestWithheldTokensToMintForConfidentialTransferFeeInstruction
} from "@solana-program/token-2022";

// Allow accounts to harvest their withheld fees to the mint, signed by the
// confidential transfer fee authority.
const enableIx = getEnableHarvestToMintInstruction({ mint, authority });

// Permissionless: move withheld fees from accounts into the mint.
const harvestIx =
  getHarvestWithheldTokensToMintForConfidentialTransferFeeInstruction({
    mint,
    sources: [sourceAccount]
  });
```

</CodeTabs>

Im JS-Client erfordert das Abheben der eingesammelten Fee aus dem Mint
(`getWithdrawWithheldTokensFromMintForConfidentialTransferFeeInstruction`)
zusätzlich einen Gleichheits- und einen Bereichsnachweis, der in
Kontextzustands-Konten verifiziert wurde, und folgt daher demselben
Proof-Account-Muster wie ein vertraulicher Transfer.

## Vertrauliches Prägen und Verbrennen

Die Erweiterung `ConfidentialMintBurn` ermöglicht es der Mint-Autorität, Angebot
direkt gegen vertrauliche Salden auszugeben und zu verbrennen, wobei das
Gesamtangebot verschlüsselt bleibt. Ein Mint mit dieser Erweiterung deaktiviert
den öffentlichen Ein- und Auszahlungspfad, da Token ausschließlich vertraulich
existieren. Weitere Informationen zum vollständigen Modell finden Sie in der
[Protokolldokumentation](https://www.solana-program.com/docs/confidential-balances).

<Callout type="info">
  Vertrauliches Prägen/Verbrennen ist am einfachsten über das
  Rust-`spl-token-client` möglich, das die erforderlichen Nachweise generiert
  und die Transaktionen für Sie sequenziert. Der `@solana-program/token-2022`
  JS-Client enthält die Low-Level-Anweisungs- Builder
  (`getConfidentialMintInstruction`, `getConfidentialBurnInstruction` und
  weitere), jedoch keinen High-Level-Helfer zum Erstellen der Nachweise, und es
  gibt keine CLI-Befehle – die folgenden Beispiele sind daher nur in Rust
  verfügbar.
</Callout>

Initialisieren Sie die Erweiterung bei der Mint-Erstellung, dann können Sie den
Vorrat über die Zeit minten, burnen und abgleichen. Beim Minting wird ein
verschlüsselter Betrag in das vertrauliche Guthaben eines Empfängers ausgegeben;
beim Burning wird ein verschlüsselter Betrag in einen ausstehenden Burn
überführt, der später in den Vorrat eingerechnet wird. Beide Vorgänge erzeugen
Nachweise wie eine vertrauliche Übertragung.

<CodeTabs>

```rust !! title="confidential-mint-burn.rs"
use spl_token_client::token::ExtensionInitializationParams;

// 1. Initialize at creation (alongside ConfidentialTransferMint).
ExtensionInitializationParams::ConfidentialMintBurn {
    supply_elgamal_pubkey, // encrypts the confidential supply
    decryptable_supply,    // AES ciphertext of the initial supply (zero)
};

// 2. Mint an encrypted amount into a recipient's confidential balance.
token
    .confidential_transfer_mint(
        &mint_authority,
        &destination_account,
        None, // equality proof account
        None, // ciphertext validity proof account
        None, // range proof account
        mint_amount,
        &supply_elgamal_keypair,
        &destination_elgamal_pubkey,
        auditor_elgamal_pubkey, // Option
        &supply_aes_key,
        None, // supply account info, fetched if None
        &[&mint_authority_keypair],
    )
    .await?;

// 3. Burn an encrypted amount from a holder's confidential balance into the
//    mint's pending burn. Generates proofs like a confidential transfer.
token
    .confidential_transfer_burn(
        &owner,
        &source_account,
        None, // equality proof account
        None, // ciphertext validity proof account
        None, // range proof account
        burn_amount,
        &source_elgamal_keypair,
        &supply_elgamal_pubkey,
        auditor_elgamal_pubkey, // Option
        &source_aes_key,
        None, // burn account info, fetched if None
        &[&owner_keypair],
    )
    .await?;

// 4. Fold the accumulated pending burn into the confidential supply.
token
    .confidential_transfer_apply_pending_burn(&mint_authority, &[&mint_authority_keypair])
    .await?;
```

</CodeTabs>

Rotieren Sie den Vorrat-Verschlüsselungsschlüssel mit
`confidential_transfer_rotate_supply_elgamal_pubkey` (der ausstehende Burn muss
zuerst null sein), und aktualisieren Sie den lesbaren Vorrat-Chiffretext mit
`confidential_transfer_update_decrypt_supply`.

## Betriebliche und Compliance-Überlegungen

- **Verwahrung des Prüferschlüssels.** Wenn Sie einen Prüfer festlegen, ist der
  geheime Prüferschlüssel ein hochwertiger Entschlüsselungsschlüssel. Bewahren
  Sie ihn sorgfältig auf, rotieren Sie ihn regelmäßig und entscheiden Sie, wer
  in Ihrer Organisation (oder welche Regulierungsbehörde) ihn verwahrt.
- **Compliance-Ausrichtung.** Die Adressprüfung und die Analyse des
  Gegenpartei-Graphen funktionieren weiterhin, da Adressen öffentlich bleiben.
  Die betragsbasierte Überwachung hängt vom Prüferschlüssel oder von der
  selektiven Offenlegung durch Konteninhaber ab. Legen Sie Ihren Ansatz vor dem
  Launch fest.
- **Onboarding von Inhabern.** Die Konfiguration eines vertraulichen Konten
  erfordert die Unterschrift des Inhabers. Um Konten für Benutzer reibungslos
  bereitzustellen, lassen Sie sie einmalig einen ElGamal-Schlüssel registrieren
  und verwenden Sie den Registry-Pfad, der im
  [Integrationsleitfaden](/docs/tokens/extensions/confidential-transfer/integration-guide#creating-and-configuring-accounts)
  beschrieben ist.
- **Transaktionsanzahl.** Eine vertrauliche Übertragung umfasst derzeit einige
  abhängige Transaktionen, da die Nachweise das aktuelle Transaktionsgrößenlimit
  überschreiten. Das Transaktionsformat v1 (mit Agave v4.2 eingeführt) erhöht
  dieses Limit und soll eine einzelne Onchain-Transaktion ermöglichen.
