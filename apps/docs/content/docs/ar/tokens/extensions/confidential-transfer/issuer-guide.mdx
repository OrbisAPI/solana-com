# إصدار رموز التحويل السري على سولانا

هذا الدليل مخصص لـ **المُصدرين**: الفرق التي تنشئ وتُشغّل نقطة سك Token-2022
تستخدم امتداد التحويل السري. يغطي القرارات التي تتخذها عند إنشاء نقطة السك
والعمليات التي تُجريها طوال دورة حياتها. للاطلاع على تدفق جانب المالك (الإيداع،
والتطبيق، والتحويل، والسحب) راجع الصفحات التفصيلية خطوة بخطوة، ولدعم هذه الرموز
في منتجك راجع
[دليل التكامل](/docs/tokens/extensions/confidential-transfer/integration-guide).

تُبقي التحويلات السرية مبالغ التحويل وأرصدة الحسابات مشفرة مع إبقاء عناوين
الحسابات ونقطة السك والملّاك علنية. تعتمد على برنامج ZK ElGamal Proof لتحقق من
الإثباتات على السلسلة، لذا فإن نقطة السك قابلة للاستخدام على الشبكات التي يكون
فيها هذا البرنامج مُفعَّلاً.

## القرارات التي تتخذها عند الإنشاء

يجب تهيئة امتداد النقل السري قبل تهيئة الـ mint ولا يمكن إضافته لاحقاً. عند
الإنشاء تقرر:

- **سياسة الموافقة**: ما إذا كان يمكن للحسابات الاشتراك في عمليات النقل السري
  بدون إذن مسبق (`auto`) أو يجب الحصول على موافقة من سلطة النقل السري للـ mint
  (`manual`).
- **المدقق**: ما إذا كان سيتم تعيين مفتاح ElGamal العام لمدقق عالمي حتى يتمكن
  طرف محدد من فك تشفير كل مبالغ التحويل للـ mint. اختياري، ويمكن تغييره لاحقاً.
- **امتدادات مصاحبة اختيارية**: رسوم النقل السري (مقترنة بامتداد رسوم النقل)
  وإنشاء/حرق السري، وكلاهما مشمول أدناه. يجب أيضاً تهيئة هذه الامتدادات عند
  الإنشاء.

## إنشاء mint سري

تُحدِّد واجهة CLI سياسة الموافقة باستخدام `--enable-confidential-transfers auto`
أو `manual`؛ يتيح `auto` لأي حامل تكوين حسابه الخاص، بينما يضع `manual` ذلك خلف
موافقة سلطة النقل السري (التي تكون افتراضياً سلطة الـ mint). تأخذ مسارات العميل
نفس الإعدادات من خلال معاملات `ConfidentialTransferMint`: سلطة، وعلامة الموافقة
التلقائية، ومفتاح مدقق اختياري. يمكن تغيير كل من سياسة الموافقة والمدقق لاحقاً
(انظر [تكوين مدقق](#configure-an-auditor))؛ فقط وجود الامتداد نفسه ثابت عند
الإنشاء.

<CodeTabs>

```terminal !! title="create-confidential-mint.sh"
$ spl-token --program-id TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb create-token --enable-confidential-transfers auto
```

```rust !! title="create-confidential-mint.rs"
use spl_token_client::token::ExtensionInitializationParams;

let extensions = vec![ExtensionInitializationParams::ConfidentialTransferMint {
    authority: Some(authority.pubkey().into()),
    auto_approve_new_accounts: true, // false for a manual approve policy
    auditor_elgamal_pubkey: None,    // Some(pubkey) to set a global auditor
}];

token
    .create_mint(&mint_authority, freeze_authority.as_ref(), extensions, &[&mint_keypair])
    .await?;
```

```ts !! title="create-confidential-mint.ts"
import { getCreateAccountInstruction } from "@solana-program/system";
import {
  extension,
  getMintSize,
  getInitializeConfidentialTransferMintInstruction,
  getInitializeMintInstruction,
  TOKEN_2022_PROGRAM_ADDRESS
} from "@solana-program/token-2022";

// Size the mint account to include the confidential transfer extension.
const space = BigInt(
  getMintSize([
    extension("ConfidentialTransferMint", {
      authority: authority.address,
      autoApproveNewAccounts: true, // false for a manual approve policy
      auditorElgamalPubkey: null // an ElGamal pubkey Address to set an auditor
    })
  ])
);
const rent = await rpc.getMinimumBalanceForRentExemption(space).send();

// Create the account, initialize the extension, then initialize the mint, in one
// transaction. The extension instruction must come before InitializeMint.
const instructions = [
  getCreateAccountInstruction({
    payer,
    newAccount: mint, // mint keypair signer
    lamports: rent,
    space,
    programAddress: TOKEN_2022_PROGRAM_ADDRESS
  }),
  getInitializeConfidentialTransferMintInstruction({
    mint: mint.address,
    authority: authority.address,
    autoApproveNewAccounts: true,
    auditorElgamalPubkey: null
  }),
  getInitializeMintInstruction({
    mint: mint.address,
    decimals,
    mintAuthority: mintAuthority.address,
    freezeAuthority: null
  })
];
// Sign with the payer and mint keypair, then send.
```

</CodeTabs>

## تكوين مدقق

المدقق العالمي هو مفتاح ElGamal العام المخزَّن على الـ mint. عند تعيينه، يُشفِّر
كل نقل سري مبلغه أيضاً باستخدام هذا المفتاح، بحيث يستطيع من يمتلك المفتاح السري
المقابل فك تشفير جميع مبالغ التحويل للـ mint. هذه هي الطريقة التي تظل بها عمليات
النقل السري متوافقة مع متطلبات التدقيق والامتثال: لا يرى الجمهور شيئاً، بينما
يرى المدقق كل شيء.

يمكن لسلطة النقل السري تعيين المدقق أو تغييره أو إزالته في أي وقت. تُحدِّث
العملية ذاتها سياسة الموافقة أيضاً. في واجهة سطر الأوامر (CLI)، يكون مفتاح
المدقق عبارة عن ترميز base64 لمفتاح عام ElGamal؛ مرِّر `--auditor-pubkey none`
لإزالته و `--approve-policy auto|manual` لتغيير السياسة.

لا يؤثر التغيير إلا على عمليات النقل المستقبلية. تبقى المبالغ في المعاملات
المسجَّلة مسبقاً على السلسلة مشفَّرةً باستخدام مفتاح المدقق الذي كان نشطاً عند
تنفيذها، لذا احتفظ بمفاتيح المدقق القديمة إذا كنت بحاجة إلى فكّ تشفير النشاط
التاريخي.

<CodeTabs>

```terminal !! title="update-confidential-settings.sh"
$ spl-token update-confidential-transfer-settings <MINT_PUBKEY> --auditor-pubkey <AUDITOR_ELGAMAL_PUBKEY>
```

```rust !! title="update-confidential-settings.rs"
token
    .confidential_transfer_update_mint(
        &authority,
        true,                         // auto_approve_new_account
        Some(auditor_elgamal_pubkey), // None to clear the auditor
        &[&authority_keypair],
    )
    .await?;
```

```ts !! title="update-confidential-settings.ts"
import { getUpdateConfidentialTransferMintInstruction } from "@solana-program/token-2022";

const ix = getUpdateConfidentialTransferMintInstruction({
  mint,
  authority, // confidential transfer authority (signer)
  autoApproveNewAccounts: true,
  auditorElgamalPubkey // an ElGamal pubkey Address, or null to clear
});
```

</CodeTabs>

<Callout type="warn">
  يستطيع المفتاح السري للمدقق فكّ تشفير كل مبالغ النقل الخاصة بالعملة. احتفظ به
  بنفس الصرامة المتبعة مع مفتاح التوقيع، وضع خطة للتغيير الدوري. يؤدي تعيين
  المدقق على `None` إلى تعطيل إمكانية رؤية المبالغ للجميع باستثناء أصحاب
  الحسابات أنفسهم.
</Callout>

## الموافقة على الحسابات (السياسة اليدوية)

في ظل سياسة الموافقة اليدوية، لا يمكن للحساب المُهيَّأ للنقل السري إجراء معاملات
سرية حتى تُوافق عليه سلطة النقل السري. يمنح هذا الجهات المُصدِرة بوابةً
للمشاركين المُدرَجين في القائمة البيضاء أو الخاضعين لإجراءات اعرف عميلك (KYC).
لا تتيح واجهة سطر الأوامر (CLI) أمر الموافقة، لذا تتم الموافقة عبر عميل برمجي.

<CodeTabs>

```rust !! title="approve-account.rs"
token
    .confidential_transfer_approve_account(
        &token_account,
        &authority,
        &[&authority_keypair],
    )
    .await?;
```

```ts !! title="approve-account.ts"
import { getApproveConfidentialTransferAccountInstruction } from "@solana-program/token-2022";

const ix = getApproveConfidentialTransferAccountInstruction({
  token, // the token account to approve
  mint,
  authority // confidential transfer authority (signer)
});
```

</CodeTabs>

## رسوم النقل السري

إذا كانت عملتك تفرض [رسوم نقل](/docs/tokens/extensions/transfer-fees) وكانت
عمليات النقل سرية، فيجب أيضاً احتجاز الرسوم بصورة سرية. تتولى امتداد
`ConfidentialTransferFeeConfig` معالجة ذلك، ويتم تهيئته عند إنشاء العملة جنباً
إلى جنب مع امتدادَي رسوم النقل والنقل السري.

تتراكم الرسوم المحتجزة مشفَّرةً على حسابات المستلمين، ثم تُجمَّع في العملة،
وبعدها يسحبها مفوَّض السحب المحتجز. تبقى جميع مبالغ الرسوم مشفَّرة طوال العملية،
ولا يُعرَّض أيٌّ من ذلك عبر واجهة سطر الأوامر (CLI). يستطيع المفتاح السري لـ
ElGamal الخاص بمفوَّض السحب المحتجز فكّ تشفير مبالغ الرسوم المحتجزة، والتي يمكن
أن تكشف بالاقتران مع معاملات الرسوم العامة عن معلومات تتعلق بمبالغ النقل، لذا
تعامل مع هذا المفتاح باعتباره بيانات حساسة.

### تهيئة إعدادات الرسوم

أدرج هذا إلى جانب `ConfidentialTransferMint` وإعداد رسوم التحويل في نفس عملية
إنشاء الـ mint.

<CodeTabs>

```rust !! title="init-confidential-fee.rs"
use spl_token_client::token::ExtensionInitializationParams;

ExtensionInitializationParams::ConfidentialTransferFeeConfig {
    authority: Some(authority.pubkey().into()),
    withdraw_withheld_authority_elgamal_pubkey: withdraw_withheld_elgamal_pubkey,
};
```

```ts !! title="init-confidential-fee.ts"
import { getInitializeConfidentialTransferFeeInstruction } from "@solana-program/token-2022";

const ix = getInitializeConfidentialTransferFeeInstruction({
  mint,
  authority, // authority allowed to change the withdraw withheld ElGamal key
  withdrawWithheldAuthorityElGamalPubkey // ElGamal pubkey Address
});
```

</CodeTabs>

### تحصيل الرسوم المحتجزة وسحبها

تحصيل الرسوم يعني نقل الرسوم المحتجزة المشفرة من الحسابات إلى الـ mint؛ أما
السحب فيعني نقلها من الـ mint إلى حساب محدد. يتضمن هذا سلطتَين، وقد تختلف أيٌّ
منهما عن سلطة الـ mint:

- **سلطة رسوم التحويل السري** (`authority` المُعيَّنة على
  `ConfidentialTransferFeeConfig`) تتيح تفعيل عملية التحصيل أو تعطيلها.
- **سلطة سحب الرسوم المحتجزة** (من `TransferFeeConfig` الخاص بامتداد رسوم
  التحويل) تسحب الرسوم المُحصَّلة خارج الـ mint.

تستلزم عمليات السحب تقديم دليل تساوٍ ودليل نطاق، يمكن تقديمهما مباشرةً أو التحقق
منهما عبر حسابات حالة السياق.

<CodeTabs>

```rust !! title="harvest-withdraw-fees.rs"
// Permissionless: move withheld fees from accounts into the mint.
token
    .confidential_transfer_harvest_withheld_tokens_to_mint(&[&source_account])
    .await?;

// Withdraw withheld fees from the mint (requires the withdraw withheld authority).
token
    .confidential_transfer_withdraw_withheld_tokens_from_mint(
        &destination_account,
        &withdraw_withheld_authority,
        None, // proof context state account, supplied inline if None
        None, // withheld tokens info, fetched if None
        &withdraw_withheld_elgamal_keypair,
        &destination_elgamal_pubkey,
        &new_decryptable_available_balance,
        &[&withdraw_withheld_authority_keypair],
    )
    .await?;
```

```ts !! title="harvest-withdraw-fees.ts"
import {
  getEnableHarvestToMintInstruction,
  getHarvestWithheldTokensToMintForConfidentialTransferFeeInstruction
} from "@solana-program/token-2022";

// Allow accounts to harvest their withheld fees to the mint, signed by the
// confidential transfer fee authority.
const enableIx = getEnableHarvestToMintInstruction({ mint, authority });

// Permissionless: move withheld fees from accounts into the mint.
const harvestIx =
  getHarvestWithheldTokensToMintForConfidentialTransferFeeInstruction({
    mint,
    sources: [sourceAccount]
  });
```

</CodeTabs>

في عميل JS، يستلزم سحب الرسوم المُحصَّلة من الـ mint
(`getWithdrawWithheldTokensFromMintForConfidentialTransferFeeInstruction`) أيضاً
تقديم دليل تساوٍ ودليل نطاق تم التحقق منهما عبر حسابات حالة السياق، وبالتالي
يتبع نفس نمط حسابات الإثبات الخاص بالتحويل السري.

## الإصدار والحرق السريَّان

يتيح امتداد `ConfidentialMintBurn` لسلطة الـ mint إصدار الرمز وحرقه mباشرةً
مقابل الأرصدة السرية، مع إبقاء إجمالي العرض مشفراً. يُعطِّل الـ mint المزوَّد
بهذا الامتداد مسار الإيداع والسحب العلني، إذ لا توجد الرموز إلا بصورة سرية. راجع
[توثيق البروتوكول](https://www.solana-program.com/docs/confidential-balances)
للاطلاع على النموذج الكامل.

<Callout type="info">
  الإصدار والحرق السريَّان أيسر ما يكونان عبر `spl-token-client` بلغة Rust، الذي
  يُولِّد الأدلة المطلوبة ويُرتِّب المعاملات تلقائياً. يتضمن عميل
  `@solana-program/token-2022` بلغة JS أدوات بناء التعليمات على المستوى المنخفض
  (`getConfidentialMintInstruction` و`getConfidentialBurnInstruction` وما
  شابهها)، غير أنه لا يشمل مساعداً رفيع المستوى لبناء الأدلة، كما لا تتوفر أوامر
  CLI، لذا فالأمثلة أدناه بلغة Rust فقط.
</Callout>

قم بتهيئة الامتداد عند إنشاء العملة، ثم اسكّ العملات واحرقها وضبط الإمداد بمرور
الوقت. يُصدر السكّ مبلغاً مشفراً في رصيد سري للمستلم؛ أما الحرق فيزيل مبلغاً
مشفراً في حرق معلّق يُدمج لاحقاً في الإمداد. كلاهما يولّد إثباتات مشابهة للتحويل
السري.

<CodeTabs>

```rust !! title="confidential-mint-burn.rs"
use spl_token_client::token::ExtensionInitializationParams;

// 1. Initialize at creation (alongside ConfidentialTransferMint).
ExtensionInitializationParams::ConfidentialMintBurn {
    supply_elgamal_pubkey, // encrypts the confidential supply
    decryptable_supply,    // AES ciphertext of the initial supply (zero)
};

// 2. Mint an encrypted amount into a recipient's confidential balance.
token
    .confidential_transfer_mint(
        &mint_authority,
        &destination_account,
        None, // equality proof account
        None, // ciphertext validity proof account
        None, // range proof account
        mint_amount,
        &supply_elgamal_keypair,
        &destination_elgamal_pubkey,
        auditor_elgamal_pubkey, // Option
        &supply_aes_key,
        None, // supply account info, fetched if None
        &[&mint_authority_keypair],
    )
    .await?;

// 3. Burn an encrypted amount from a holder's confidential balance into the
//    mint's pending burn. Generates proofs like a confidential transfer.
token
    .confidential_transfer_burn(
        &owner,
        &source_account,
        None, // equality proof account
        None, // ciphertext validity proof account
        None, // range proof account
        burn_amount,
        &source_elgamal_keypair,
        &supply_elgamal_pubkey,
        auditor_elgamal_pubkey, // Option
        &source_aes_key,
        None, // burn account info, fetched if None
        &[&owner_keypair],
    )
    .await?;

// 4. Fold the accumulated pending burn into the confidential supply.
token
    .confidential_transfer_apply_pending_burn(&mint_authority, &[&mint_authority_keypair])
    .await?;
```

</CodeTabs>

قم بتدوير مفتاح تشفير الإمداد باستخدام
`confidential_transfer_rotate_supply_elgamal_pubkey` (يجب أن يكون الحرق المعلّق
صفراً أولاً)، وقم بتحديث نص الإمداد المقروء المشفر باستخدام
`confidential_transfer_update_decrypt_supply`.

## اعتبارات التشغيل والامتثال

- **حفظ مفتاح المدقق.** إذا قمت بتعيين مدقق، فإن المفتاح السري للمدقق يُعدّ
  مفتاح فك تشفير عالي القيمة. قم بتخزينه وتدويره بعناية، وحدد من في مؤسستك (أو
  أي جهة تنظيمية) يحتفظ به.
- **موقف الامتثال.** يستمر فحص العناوين وتحليل مخطط الأطراف المقابلة في العمل
  لأن العناوين تبقى عامة. يعتمد المراقبة القائمة على المبالغ على مفتاح المدقق أو
  على الإفصاح الانتقائي من أصحاب الحسابات. حدد نهجك قبل الإطلاق.
- **إعداد حاملي الحسابات.** يتطلب تهيئة حساب سري توقيع المالك. لتوفير الحسابات
  للمستخدمين بسلاسة، اطلب منهم تسجيل مفتاح ElGamal مرة واحدة واستخدام مسار
  السجل، الموضح في
  [دليل التكامل](/docs/tokens/extensions/confidential-transfer/integration-guide#creating-and-configuring-accounts).
- **عدد المعاملات.** يمتد التحويل السري حالياً عبر عدة معاملات مترابطة لأن
  الإثباتات تتجاوز حد حجم المعاملات الحالي. يرفع تنسيق المعاملة v1 (الذي سيُطلق
  مع Agave v4.2) هذا الحد ومن المتوقع أن يسمح بمعاملة واحدة على السلسلة.
