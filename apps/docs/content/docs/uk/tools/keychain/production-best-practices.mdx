Keychain абстрагує бекенд підписання, але експлуатація підписувача у виробничому
середовищі залишається вашою відповідальністю. Ці практики застосовуються до
всіх бекендів; див. [Вибір бекенду](/docs/tools/keychain/choosing-a-backend) для
вибору відповідного.

## Розділяйте гарячі та холодні підписувачі

Використовуйте операційний підписувач із низьким балансом ("гарячий") для частих
автоматизованих транзакцій та окремий підписувач для цінних активів ("холодний")
для переміщення коштів казначейства. Підкріпіть холодний підписувач
MPC-кастодією або хмарним HSM і вимагайте політик затвердження перед
підписанням. Оскільки інтерфейс ідентичний, кожна роль може використовувати
різний бекенд без змін у точках виклику.

## Виконуйте ротацію ключів свідомо

У Solana ключ підписання _є_ адресою облікового запису, тому ротація ключа
створює нову адресу. Плануйте ротацію як міграцію: створіть новий ключ,
переназначте відповідні повноваження (або перемістіть кошти) на нову адресу, а
потім виведіть з обігу старий. Використовуйте окремі ключі для кожного
середовища, щоб ключі devnet ніколи не використовувалися повторно в mainnet.

## Надавайте доступ за принципом найменших привілеїв

Обмежте облікові дані кожного бекенду до мінімально необхідного для підписання.
Для AWS KMS це `kms:Sign` та `kms:DescribeKey` для конкретного ключа; надавайте
перевагу ролям IAM над статичними обліковими даними. Застосовуйте той самий
принцип до політик Vault та ключів API керованих гаманців.

## Плануйте доступність

Віддалені бекенди залежать від мережевого сервісу. Викликайте `isAvailable()`
перед тим, як покладатися на підписувача, застосовуйте повторні спроби з
відступом при тимчасових збоях та визначте резервний шлях на випадок перебоїв.
Keychain забезпечує HTTPS для віддалених бекендів та застосовує стандартний
тайм-аут запиту.

## Захистіть секрети та транспорт

- Усі віддалені бекенди взаємодіють через HTTPS; кінцеві точки без HTTPS
  відхиляються.
- Надавайте ключі API, токени та облікові дані з менеджера секретів або змінних
  середовища — ніколи не вписуйте їх у код і не фіксуйте в системі контролю
  версій.
- Keychain очищає відповіді про помилки, щоб уникнути витоку секретів у журнали;
  тримайте власні журнали вільними від необроблених облікових даних і ключового
  матеріалу.

## Моніторинг та аудит підписання

Відстежуйте частку успішних підписань, затримку та кількість збоїв, і
налаштовуйте сповіщення про сплески — дивіться метрики в розділі
[Готовність до production](/docs/payments/production-readiness#monitoring).
Увімкніть журнали аудиту на стороні провайдера (KMS, Vault або кастодіана) та
звіряйте їх із транзакціями, які надсилає ваш застосунок.
