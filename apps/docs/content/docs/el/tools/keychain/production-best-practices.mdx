Το Keychain αφαιρεί την πολυπλοκότητα του backend υπογραφής, αλλά η λειτουργία
ενός signer σε παραγωγή παραμένει δική σας ευθύνη. Αυτές οι πρακτικές
εφαρμόζονται σε όλα τα backends· ανατρέξτε στο
[Επιλογή backend](/docs/tools/keychain/choosing-a-backend) για την επιλογή του
κατάλληλου.

## Διαχωρίστε τους hot και cold signers

Χρησιμοποιήστε έναν λειτουργικό signer με χαμηλό υπόλοιπο ("hot") για συχνές,
αυτοματοποιημένες συναλλαγές, και έναν ξεχωριστό signer υψηλής αξίας ("cold")
για κινήσεις ταμείου. Υποστηρίξτε τον cold signer με MPC custody ή cloud HSM και
απαιτήστε πολιτικές έγκρισης πριν από την υπογραφή. Επειδή η διεπαφή είναι
πανομοιότυπη, κάθε ρόλος μπορεί να χρησιμοποιεί διαφορετικό backend χωρίς
αλλαγές στα σημεία κλήσης.

## Εναλλάσσετε κλειδιά με πρόνοια

Στο Solana το κλειδί υπογραφής _είναι_ η διεύθυνση λογαριασμού, οπότε η εναλλαγή
κλειδιού παράγει νέα διεύθυνση. Σχεδιάστε την εναλλαγή ως μετεγκατάσταση: παροχή
νέου κλειδιού, ανάθεση των σχετικών αρχών (ή μεταφορά κεφαλαίων) στη νέα
διεύθυνση, και στη συνέχεια απόσυρση του παλιού. Χρησιμοποιήστε διακριτά κλειδιά
ανά περιβάλλον, ώστε τα κλειδιά devnet να μην επαναχρησιμοποιούνται ποτέ στο
mainnet.

## Εκχωρήστε πρόσβαση ελάχιστων προνομίων

Περιορίστε τα διαπιστευτήρια κάθε backend στο ελάχιστο που απαιτείται για
υπογραφή. Για το AWS KMS, αυτό είναι `kms:Sign` και `kms:DescribeKey` στο
συγκεκριμένο κλειδί· προτιμήστε τους ρόλους IAM έναντι στατικών διαπιστευτηρίων.
Εφαρμόστε την ίδια αρχή στις πολιτικές Vault και στα κλειδιά API διαχειριζόμενου
πορτοφολιού.

## Σχεδιάστε για διαθεσιμότητα

Τα απομακρυσμένα backends εξαρτώνται από μια υπηρεσία δικτύου. Καλέστε
`isAvailable()` πριν βασιστείτε σε έναν signer, εφαρμόστε επαναλήψεις με backoff
σε παροδικές αποτυχίες, και ορίστε ένα εναλλακτικό μονοπάτι για διακοπές. Το
Keychain επιβάλλει HTTPS για απομακρυσμένα backends και εφαρμόζει προεπιλεγμένο
χρονικό όριο αιτήματος.

## Προστασία μυστικών και μεταφοράς

- Όλα τα απομακρυσμένα backends επικοινωνούν μέσω HTTPS· τα endpoints που δεν
  χρησιμοποιούν HTTPS απορρίπτονται.
- Παρέχετε κλειδιά API, tokens και διαπιστευτήρια από έναν διαχειριστή μυστικών
  ή μεταβλητές περιβάλλοντος — μην τα ενσωματώνετε ποτέ στον κώδικα ή τα
  υποβάλλετε στο σύστημα ελέγχου εκδόσεων.
- Το Keychain εξυγιαίνει τις αποκρίσεις σφαλμάτων για να αποφεύγεται η διαρροή
  μυστικών στα logs· διατηρείτε τα δικά σας logs ελεύθερα από ακατέργαστα
  διαπιστευτήρια και υλικό κλειδιών.

## Παρακολούθηση και έλεγχος υπογραφής

Παρακολουθείτε τον ρυθμό επιτυχίας υπογραφής, την καθυστέρηση και τον αριθμό
αποτυχιών, και ρυθμίστε ειδοποιήσεις για απότομες αυξήσεις — δείτε τις μετρικές
στο [Production Readiness](/docs/payments/production-readiness#monitoring).
Ενεργοποιήστε τα αρχεία ελέγχου από την πλευρά του παρόχου (KMS, Vault ή
θεματοφύλακα) και συμφωνείτε τα με τις συναλλαγές που υποβάλλει η εφαρμογή σας.
