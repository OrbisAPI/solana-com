# Vertrouwelijke Transfer-tokens uitgeven op Solana

Deze handleiding is bedoeld voor **uitgevers**: teams die een Token-2022-mint
aanmaken en beheren die gebruikmaakt van de Confidential Transfer-extensie. Het
behandelt de keuzes die u maakt bij het aanmaken van de mint en de bewerkingen
die u uitvoert gedurende de levensduur van de mint. Voor de houderszijde
(storten, toepassen, overmaken, opnemen) zie de stapsgewijze pagina's, en voor
de ondersteuning van deze tokens in een product zie de
[Integratiehandleiding](/docs/tokens/extensions/confidential-transfer/integration-guide).

Vertrouwelijke overdrachten houden overdrachtsbedragen en accountsaldi
versleuteld, terwijl accountadressen, de mint en eigenaren openbaar blijven. Ze
zijn afhankelijk van het ZK ElGamal Proof Program voor
onchain-bewijsverificatie, waardoor de mint bruikbaar is op clusters waar dat
programma is ingeschakeld.

## Beslissingen die je bij aanmaak neemt

De Confidential Transfer-extensie moet worden geïnitialiseerd voordat de mint
wordt geïnitialiseerd en kan later niet meer worden toegevoegd. Bij aanmaak
bepaal je:

- **Goedkeuringsbeleid**: of accounts zich permissieloos kunnen aanmelden voor
  vertrouwelijke overdrachten (`auto`) of goedkeuring vereisen van de
  vertrouwelijke overdrachtsautoriteit van de mint (`manual`).
- **Auditor**: of een globale auditor ElGamal pubkey moet worden ingesteld,
  zodat een aangewezen partij elk overdrachtsbedrag voor de mint kan
  ontcijferen. Optioneel en kan later worden gewijzigd.
- **Optionele bijbehorende extensies**: vertrouwelijke overdrachtskosten
  (gekoppeld aan de overdrachtskosten-extensie) en vertrouwelijk
  munten/verbranden, beide hieronder beschreven. Deze moeten ook bij aanmaak
  worden geïnitialiseerd.

## Een vertrouwelijke mint aanmaken

De CLI stelt het goedkeuringsbeleid in met
`--enable-confidential-transfers auto` of `manual`; `auto` laat elke houder zijn
eigen account configureren, terwijl `manual` dit achter goedkeuring van de
vertrouwelijke overdrachtsautoriteit plaatst (die standaard de mint-autoriteit
is). De clientpaden nemen dezelfde instellingen via de
`ConfidentialTransferMint`-parameters: een autoriteit, de automatische
goedkeuringsvlag en een optionele auditorsleutel. Zowel het goedkeuringsbeleid
als de auditor kunnen later worden gewijzigd (zie
[Een auditor configureren](#configure-an-auditor)); alleen de aanwezigheid van
de extensie zelf ligt vast bij aanmaak.

<CodeTabs>

```terminal !! title="create-confidential-mint.sh"
$ spl-token --program-id TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb create-token --enable-confidential-transfers auto
```

```rust !! title="create-confidential-mint.rs"
use spl_token_client::token::ExtensionInitializationParams;

let extensions = vec![ExtensionInitializationParams::ConfidentialTransferMint {
    authority: Some(authority.pubkey().into()),
    auto_approve_new_accounts: true, // false for a manual approve policy
    auditor_elgamal_pubkey: None,    // Some(pubkey) to set a global auditor
}];

token
    .create_mint(&mint_authority, freeze_authority.as_ref(), extensions, &[&mint_keypair])
    .await?;
```

```ts !! title="create-confidential-mint.ts"
import { getCreateAccountInstruction } from "@solana-program/system";
import {
  extension,
  getMintSize,
  getInitializeConfidentialTransferMintInstruction,
  getInitializeMintInstruction,
  TOKEN_2022_PROGRAM_ADDRESS
} from "@solana-program/token-2022";

// Size the mint account to include the confidential transfer extension.
const space = BigInt(
  getMintSize([
    extension("ConfidentialTransferMint", {
      authority: authority.address,
      autoApproveNewAccounts: true, // false for a manual approve policy
      auditorElgamalPubkey: null // an ElGamal pubkey Address to set an auditor
    })
  ])
);
const rent = await rpc.getMinimumBalanceForRentExemption(space).send();

// Create the account, initialize the extension, then initialize the mint, in one
// transaction. The extension instruction must come before InitializeMint.
const instructions = [
  getCreateAccountInstruction({
    payer,
    newAccount: mint, // mint keypair signer
    lamports: rent,
    space,
    programAddress: TOKEN_2022_PROGRAM_ADDRESS
  }),
  getInitializeConfidentialTransferMintInstruction({
    mint: mint.address,
    authority: authority.address,
    autoApproveNewAccounts: true,
    auditorElgamalPubkey: null
  }),
  getInitializeMintInstruction({
    mint: mint.address,
    decimals,
    mintAuthority: mintAuthority.address,
    freezeAuthority: null
  })
];
// Sign with the payer and mint keypair, then send.
```

</CodeTabs>

## Een auditor configureren

Een globale auditor is een ElGamal pubkey die is opgeslagen op de mint. Wanneer
ingesteld, versleutelt elke vertrouwelijke overdracht bovendien het bedrag onder
deze sleutel, zodat degene die de bijbehorende geheime sleutel bezit alle
overdrachtsbedragen voor de mint kan ontcijferen. Dit is hoe vertrouwelijke
overdrachten compatibel blijven met audit- en nalevingsvereisten: het publiek
ziet niets, de auditor ziet alles.

De vertrouwelijke overdrachtsbeheerder kan de auditor op elk moment instellen,
roteren of verwijderen. Dezelfde bewerking werkt ook het goedkeuringsbeleid bij.
Op de CLI is de auditorsleutel een base64-codering van een ElGamal publieke
sleutel; geef `--auditor-pubkey none` door om deze te verwijderen en
`--approve-policy auto|manual` om het beleid te wijzigen.

Rotatie heeft alleen invloed op toekomstige overdrachten. Bedragen in
transacties die al op de blockchain staan, blijven versleuteld met de
auditorsleutel die actief was toen ze werden uitgevoerd. Bewaar daarom oude
auditorsleutels als u historische activiteit wilt ontsleutelen.

<CodeTabs>

```terminal !! title="update-confidential-settings.sh"
$ spl-token update-confidential-transfer-settings <MINT_PUBKEY> --auditor-pubkey <AUDITOR_ELGAMAL_PUBKEY>
```

```rust !! title="update-confidential-settings.rs"
token
    .confidential_transfer_update_mint(
        &authority,
        true,                         // auto_approve_new_account
        Some(auditor_elgamal_pubkey), // None to clear the auditor
        &[&authority_keypair],
    )
    .await?;
```

```ts !! title="update-confidential-settings.ts"
import { getUpdateConfidentialTransferMintInstruction } from "@solana-program/token-2022";

const ix = getUpdateConfidentialTransferMintInstruction({
  mint,
  authority, // confidential transfer authority (signer)
  autoApproveNewAccounts: true,
  auditorElgamalPubkey // an ElGamal pubkey Address, or null to clear
});
```

</CodeTabs>

<Callout type="warn">
  De geheime auditorsleutel kan elk overdrachtsbedrag voor de mint ontsleutelen.
  Bewaar deze met dezelfde zorgvuldigheid als een ondertekeningssleutel en plan
  voor rotatie. Het instellen van de auditor op `None` schakelt de zichtbaarheid
  van bedragen uit voor iedereen, behalve voor de rekeninghouders zelf.
</Callout>

## Accounts goedkeuren (handmatig beleid)

Met een handmatig goedkeuringsbeleid kan een account dat is geconfigureerd voor
vertrouwelijke overdrachten niet vertrouwelijk transacties uitvoeren totdat de
vertrouwelijke overdrachtsbeheerder het goedkeurt. Dit geeft uitgevers een
toegangscontrole voor deelnemers op een allowlist of met KYC-verificatie. De CLI
heeft geen goedkeuringscommando, waardoor goedkeuring via een client moet worden
gedaan.

<CodeTabs>

```rust !! title="approve-account.rs"
token
    .confidential_transfer_approve_account(
        &token_account,
        &authority,
        &[&authority_keypair],
    )
    .await?;
```

```ts !! title="approve-account.ts"
import { getApproveConfidentialTransferAccountInstruction } from "@solana-program/token-2022";

const ix = getApproveConfidentialTransferAccountInstruction({
  token, // the token account to approve
  mint,
  authority // confidential transfer authority (signer)
});
```

</CodeTabs>

## Vertrouwelijke overdrachtskosten

Als uw mint [overdrachtskosten](/docs/tokens/extensions/transfer-fees) in
rekening brengt en overdrachten vertrouwelijk zijn, moeten de kosten ook
vertrouwelijk worden ingehouden. De extensie `ConfidentialTransferFeeConfig`
regelt dit en wordt bij het aanmaken van de mint geïnitialiseerd naast zowel de
overdrachtskosten- als de vertrouwelijke overdrachtsextensies.

Ingehouden kosten worden versleuteld opgebouwd op ontvangeraccounts, worden naar
de mint overgebracht en vervolgens opgenomen door de autoriteit voor het opnemen
van ingehouden bedragen. Elk kostenbedrag blijft gedurende het hele proces
versleuteld. Dit is niet beschikbaar via de CLI. De geheime ElGamal-sleutel van
de autoriteit voor ingehouden bedragen kan versleutelde kostenbedragen
ontsleutelen, wat in combinatie met de openbare kostenparameters informatie over
overdrachtsbedragen kan onthullen. Behandel die sleutel daarom als gevoelig.

### Initialiseer de vergoedingsconfiguratie

Voeg dit toe samen met `ConfidentialTransferMint` en de configuratie voor
overdrachtkosten in dezelfde muntcreatie.

<CodeTabs>

```rust !! title="init-confidential-fee.rs"
use spl_token_client::token::ExtensionInitializationParams;

ExtensionInitializationParams::ConfidentialTransferFeeConfig {
    authority: Some(authority.pubkey().into()),
    withdraw_withheld_authority_elgamal_pubkey: withdraw_withheld_elgamal_pubkey,
};
```

```ts !! title="init-confidential-fee.ts"
import { getInitializeConfidentialTransferFeeInstruction } from "@solana-program/token-2022";

const ix = getInitializeConfidentialTransferFeeInstruction({
  mint,
  authority, // authority allowed to change the withdraw withheld ElGamal key
  withdrawWithheldAuthorityElGamalPubkey // ElGamal pubkey Address
});
```

</CodeTabs>

### Oogst en onttrek ingehouden vergoedingen

Oogsten verplaatst de versleutelde ingehouden vergoedingen van accounts naar de
mint; onttrekken verplaatst ze uit de mint naar een gekozen account. Twee
autoriteiten zijn betrokken, en elk kan afwijken van de mint-autoriteit:

- De **vertrouwelijke overdrachtvergoedingsautoriteit** (de `authority`
  ingesteld op `ConfidentialTransferFeeConfig`) schakelt het oogsten in of uit.
- De **autoriteit voor het onttrekken van ingehouden bedragen** (van de
  `TransferFeeConfig` van de overdrachtvergoedingsextensie) onttrekt de geoogste
  vergoedingen uit de mint.

Onttrekkingen vereisen een gelijkheids- en bereikbewijs, inline aangeleverd of
geverifieerd in contextstatusaccounts.

<CodeTabs>

```rust !! title="harvest-withdraw-fees.rs"
// Permissionless: move withheld fees from accounts into the mint.
token
    .confidential_transfer_harvest_withheld_tokens_to_mint(&[&source_account])
    .await?;

// Withdraw withheld fees from the mint (requires the withdraw withheld authority).
token
    .confidential_transfer_withdraw_withheld_tokens_from_mint(
        &destination_account,
        &withdraw_withheld_authority,
        None, // proof context state account, supplied inline if None
        None, // withheld tokens info, fetched if None
        &withdraw_withheld_elgamal_keypair,
        &destination_elgamal_pubkey,
        &new_decryptable_available_balance,
        &[&withdraw_withheld_authority_keypair],
    )
    .await?;
```

```ts !! title="harvest-withdraw-fees.ts"
import {
  getEnableHarvestToMintInstruction,
  getHarvestWithheldTokensToMintForConfidentialTransferFeeInstruction
} from "@solana-program/token-2022";

// Allow accounts to harvest their withheld fees to the mint, signed by the
// confidential transfer fee authority.
const enableIx = getEnableHarvestToMintInstruction({ mint, authority });

// Permissionless: move withheld fees from accounts into the mint.
const harvestIx =
  getHarvestWithheldTokensToMintForConfidentialTransferFeeInstruction({
    mint,
    sources: [sourceAccount]
  });
```

</CodeTabs>

In de JS-client vereist het onttrekken van de geoogste vergoedingen uit de mint
(`getWithdrawWithheldTokensFromMintForConfidentialTransferFeeInstruction`)
bovendien een gelijkheids- en bereikbewijs geverifieerd in
contextstatusaccounts, waardoor het hetzelfde bewijs-accountpatroon volgt als
een vertrouwelijke overdracht.

## Vertrouwelijk minten en verbranden

De `ConfidentialMintBurn` extensie stelt de mint-autoriteit in staat om aanbod
direct uit te geven en te verbranden via vertrouwelijke saldi, waarbij het
totale aanbod versleuteld blijft. Een mint met deze extensie schakelt het
openbare storten en opnemen uit, omdat tokens uitsluitend vertrouwelijk bestaan.
Zie de
[protocoldocumentatie](https://www.solana-program.com/docs/confidential-balances)
voor het volledige model.

<Callout type="info">
  Vertrouwelijk minten/verbranden gaat het eenvoudigst via de Rust
  `spl-token-client`, die de vereiste bewijzen genereert en de transacties voor
  u in volgorde uitvoert. De `@solana-program/token-2022` JS-client levert de
  low-level instructiebouwers (`getConfidentialMintInstruction`,
  `getConfidentialBurnInstruction`, en aanverwante) maar geen high-level helper
  die de bewijzen opbouwt, en er zijn geen CLI-opdrachten, dus de onderstaande
  voorbeelden zijn alleen in Rust.
</Callout>

Initialiseer de extensie bij het aanmaken van de mint, en mint, burn en
reconcilieer daarna de voorraad in de loop van de tijd. Minting geeft een
versleuteld bedrag uit naar het vertrouwelijke saldo van een ontvanger; burning
verwijdert een versleuteld bedrag naar een openstaande burn die later wordt
samengevoegd met de voorraad. Beide genereren bewijzen zoals een vertrouwelijke
overdracht.

<CodeTabs>

```rust !! title="confidential-mint-burn.rs"
use spl_token_client::token::ExtensionInitializationParams;

// 1. Initialize at creation (alongside ConfidentialTransferMint).
ExtensionInitializationParams::ConfidentialMintBurn {
    supply_elgamal_pubkey, // encrypts the confidential supply
    decryptable_supply,    // AES ciphertext of the initial supply (zero)
};

// 2. Mint an encrypted amount into a recipient's confidential balance.
token
    .confidential_transfer_mint(
        &mint_authority,
        &destination_account,
        None, // equality proof account
        None, // ciphertext validity proof account
        None, // range proof account
        mint_amount,
        &supply_elgamal_keypair,
        &destination_elgamal_pubkey,
        auditor_elgamal_pubkey, // Option
        &supply_aes_key,
        None, // supply account info, fetched if None
        &[&mint_authority_keypair],
    )
    .await?;

// 3. Burn an encrypted amount from a holder's confidential balance into the
//    mint's pending burn. Generates proofs like a confidential transfer.
token
    .confidential_transfer_burn(
        &owner,
        &source_account,
        None, // equality proof account
        None, // ciphertext validity proof account
        None, // range proof account
        burn_amount,
        &source_elgamal_keypair,
        &supply_elgamal_pubkey,
        auditor_elgamal_pubkey, // Option
        &source_aes_key,
        None, // burn account info, fetched if None
        &[&owner_keypair],
    )
    .await?;

// 4. Fold the accumulated pending burn into the confidential supply.
token
    .confidential_transfer_apply_pending_burn(&mint_authority, &[&mint_authority_keypair])
    .await?;
```

</CodeTabs>

Roteer de versleutelingssleutel voor de voorraad met
`confidential_transfer_rotate_supply_elgamal_pubkey` (de openstaande burn moet
eerst nul zijn), en ververs de leesbare voorraad-ciphertext met
`confidential_transfer_update_decrypt_supply`.

## Operationele en compliance-overwegingen

- **Bewaring van de auditeursleutel.** Als u een auditor instelt, is de geheime
  sleutel van de auditor een hoogwaardige decryptiesleutel. Bewaar en roteer
  deze zorgvuldig, en bepaal wie binnen uw organisatie (of welke toezichthouder)
  deze beheert.
- **Compliance-houding.** Adresscreening en analyse van het tegenpartijnetwerk
  blijven werken omdat adressen openbaar blijven. Monitoring op basis van
  bedragen is afhankelijk van de auditeursleutel of van selectieve
  openbaarmaking door rekeninghouders. Bepaal uw aanpak vóór de lancering.
- **Gebruikers onboarden.** Voor het configureren van een vertrouwelijke
  rekening is de handtekening van de eigenaar vereist. Om accounts voor
  gebruikers soepel in te richten, laat u hen eenmalig een ElGamal-sleutel
  registreren en gebruikt u het registerpad, beschreven in de
  [Integratiegids](/docs/tokens/extensions/confidential-transfer/integration-guide#creating-and-configuring-accounts).
- **Transactieaantal.** Een vertrouwelijke overdracht omvat momenteel een aantal
  afhankelijke transacties, omdat de bewijzen de huidige transactiegroottlimiet
  overschrijden. Transactieformaat v1 (geïntroduceerd met Agave v4.2) verhoogt
  die limiet en zal naar verwachting één enkele on-chain transactie mogelijk
  maken.
